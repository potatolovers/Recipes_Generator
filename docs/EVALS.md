# 菜谱导入：Eval范围与题目草案

## 四类评测范围

当前先明确测什么；具体指标、评分阈值、dataset规模和标注流程后续单独设计，不把旧题目数量当成发布门槛。

| 类别 | 评测问题 | 预期行为 |
| --- | --- | --- |
| 1. 输入判断 | 输入可直接提取、内容不全/模糊，还是不相关？ | 可提取则提取；缺失/模糊则识别已知与未知，再判断补全或请求补充；不相关则拒绝 |
| 2. 原文提取 | 输出是否忠实于输入？ | 菜名、食材、用量、步骤、顺序与证据一致；不遗漏、不曲解；预估不能记为提取正确 |
| 3. AI补全 | 缺失内容补得是否合理、可执行？ | 不与明确事实冲突；预估有标记与依据；无法合理推断时保留未知，而非强行生成 |
| 4. 可靠性（建议范围，待确认） | 异常情况下能否正确失败并恢复？ | 覆盖输入/媒体无效、网络/工具/模型超时、坏JSON/证据、取消/迟到响应、重试重复及本地保存；不白屏、不假成功、不丢已保存数据 |

“可提取”与“内容不全”不是每个字段都二选一：同一帖子可有明确食材和未知用量。输入级判断用于确定处理方式，字段级来源标记用于评估结果。空输入/损坏文件先判无效，不强制归为不相关。
四类分别报告；V1优先功能与准确性，成本/延迟先记录，V2再做性能优化评测。可靠性中的超时处理不等同于追求更低延迟。

输出验收新增：不同语言输入仍输出英文菜谱及英文Estimated/AI recommendation说明，保留原文证据；冲突检测排除等价单位、不同阶段/份数、缺失和可选版本。具体冲突类型见RECIPE_CONTRACT第5节，仍待审阅，不把所有差异都要求用户确认。

Agent 服务的 eval（`agent/evals/dishes.json`、`agent/evals/retrieval_cases.json`）已按英语用户视角改写（2026-10-22，产品面向英语用户）。下方 25 条为早期中文草案，待按同一原则改写。

## 现有25条题目草案

Agents API 接入新增待验证：图片独有事实可提取、模糊图片不伪造；工具请求/回传完整，重复事件不重复入库；会话隔离、取消与迟到响应、坏JSON不假成功。真实模型与模拟工具测试分别记录；尚未执行，具体指标仍待设计。

知识库方向新增待设计场景：命中已有知识、缺失时外部获取、来源不可用、来源冲突、重复/过期资料、错误候选不进入可信知识。验证知识依据和原视频证据不混淆；模型生成内容不得自证为外部事实。入库指标/门槛尚待确定。

2026-09-28新增产品约束见 [W1.1契约](RECIPE_CONTRACT.md) 与 [3个用户样例](RECIPE_EXAMPLES.md)。指标/dataset仍待设计；补充覆盖描述/作者网站取证后重新分类、纯音乐视频补全、冲突来源与AI推荐、美制/°F、每步用量与半成品、份数范围和并行总时间。三个期望输出不是已核实的原文标签。
旧题的原文事实先用原单位核对；最终展示统一美制/°F，允许正确换算，不能因保留旧题公制措辞而判美制输出错误。新增材料不得重复计数，预估不能伪造证据。

25 条，**全部待人工执行**。这是产品验收题，不是现有能力声明；demo 的固定输出不能作为模型通过依据。
每次记录：题号、模型/提示词/代码版本、实际输出、通过/失败/阻塞、run_id。文本可直接测试；图片/视频题需按描述准备固定素材并保存，缺素材记“阻塞”。
共同标准：JSON 合法；原文提取不编造；补全必须显式标注；证据引用真实存在且支持结论；失败不伪装成功。

**适用边界**：原有内容题衡量“原文提取”，提取部分未知值仍保留未知；不代表禁止另行标注AI预估。三类输入判断和AI补全案例尚待补齐。按 [MILESTONES](MILESTONES.md)，W1确定范围、W2设计首版指标/dataset并初评；原“至少30条/90%”不作为已定标准。

执行顺序：V1/P0 先跑文字/图片与错误处理题；P1 加视频帧/转写；P2 加两平台真实链接。V1 优先准确与可用，成本/延迟只记录；第25题作为 V2 配额验收。V2 对同题比较质量/成本/延迟，允许质量下降幅度待定；V3 另补容量和同步测试。
阶段验收还需记录：P0 重启后本地菜谱恢复；P1 视频任务取消/重试；P2 TikTok/Bilibili 各一成功、一失效链接。文字题不能代替这些端到端检查。
